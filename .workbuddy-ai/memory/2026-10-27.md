### Root cause of "capture needs the button"
Two authorities measured the same angle from *different target positions*:
`AlignmentCalculator` aimed at the **live anchor pose** (adopted from
`PlaneAnchorService.refresh`, which overwrites `AnchoredTarget.worldPosition`
with ARCore's refined pose twice a second), while
`VioSphereEngine.evaluateFrame` aimed at the **frozen node**
(`station + radius × direction`). At r = 1.0 m a few cm of anchor refinement is
several degrees, so `readyToCapture` could be true while
`gate.canTriggerShutter` was false. The button only reads `readyToCapture`; the
auto path conjoined both. Hence: manual works, automatic never fires.

Fix: both now read `_immutableTargetPosition()` (engine node) — the brief's
"immutable world position" authority. The live anchor pose is still read for
`activeAnchorTracking` only.

### Guidance oscillation
`CaptureState.guidance` called `guidanceStateOf(previous: null)` on every
build, so the documented hysteresis band never applied — the indicator flipped
at the raw 3.0° boundary (2.90/3.10/3.12 in the logs). Replaced with a **time
latch**: entry and exit both at tolerance (clamped to it, so `aligned` can
never claim an aim the shutter refuses), plus `alignedHeldMs >= 200 ms` to
enter. The 600 ms stability window is longer than the latch, so it never delays
a real capture. Controller now carries `previousGuidance` + `alignedHeldMs`.

### Automatic capture machine
`_autoCaptureVerdict` evaluates the 12 conditions per frame and returns
`(eligible, stage, block)`. Atomic `waiting → capturing` happens in `_shoot`
synchronously before the first await (new `CaptureTargetStatus.capturing`,
read back as `pending` on load so an interrupted capture stays retryable).
`_shoot` is the single transaction both `captureNow()` (manual) and the machine
(automatic) enter, tagged with `CaptureTriggerSource` for the log.

New public API: `CaptureController.mode` / `setCaptureMode`, `autoStage`,
`autoBlockReason`; `CaptureState.mode`, `autoStage`, `autoBlockReason`,
`captureStatus`, `guidanceValid`, `previousGuidance`, `alignedHeldMs`.

### Constraints
All engine constants verified unchanged: drift 0.20 m, alignment 3.0°, pose age
250 ms, window 600 ms, orientation drift 1.5°, position drift 0.03 m, angular
rate 5°/s.

### Not done (deliberately)
No build, analyzer, formatter or test run — user validates on device. Physical
behaviour is therefore unverified.
