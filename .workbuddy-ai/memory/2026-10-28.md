## Backend Python environment: `Unresolved reference 'fastapi'`

IDE error reported against `backend/`. Diagnosis: not a code defect — the
backend had **no virtual environment** and `fastapi` was installed nowhere.
`pyproject.toml` declares `requires-python >= 3.12`; system Python is 3.11.8
(too old), managed 3.13.12 satisfied it.

Fix (user chose uv over plain venv):
1. `pip install uv` into the managed 3.13.12 → uv 0.13.6.
2. `uv sync --python <managed 3.13.12>` in `backend/` → created `backend/.venv`
   (Python 3.13.14, uv picked a newer patch), 44 packages incl. fastapi 0.162.0.

### Two real defects found while verifying

- **Missing `[build-system]`** — the `src/` layout had no build backend, so uv
  treated the project as *virtual*: dependencies installed but `src/sitesense`
  never reached `sys.path`, making `import sitesense` fail. Added hatchling +
  `[tool.hatch.build.targets.wheel] packages = ["src/sitesense"]`. Re-synced →
  project installs editable.
- **`core/config.py` imported `BaseSettings` from `pydantic`** — moved to
  `pydantic-settings` in Pydantic v2, raised `PydanticImportError` at import
  time and took the whole app down. Fixed the import (dependency was already
  declared).

Also: added `backend/.gitignore` (`.venv/` 97 MB was untracked and unignored;
note the git repo root is `C:/Users/Lenovo`, not the project dir), and added
`B008` to ruff's ignore list (FastAPI `Depends()` in defaults is the documented
pattern, not a mutable-default bug — removed 13 false positives).

### Verified
`fastapi 0.162.0`; `sitesense.main.app` → `FastAPI`; `get_settings()` loads
`sqlite+aiosqlite:///./var/sitesense.db`; `pytest -q` → 1 passed.

Remaining ruff findings are style only (25 E501, 9 I001, 2 UP017, 1 UP042,
1 F401) — deliberately not mass-fixed.

**User action still required:** point the IDE interpreter at

## Follow-up: why the IDE "does not detect" the interpreter

Investigated the IDE state directly (not guesswork). Findings:

- Running IDE: `C:\Program Files\Android\Android Studio\studio64.exe`,
  build **AI-261.23567.138.2611.15646644** = Android Studio 2026.1.1. Two
  config dirs exist (`AndroidStudio2025.2.3`, `AndroidStudio2026.1.1`); the
  `python-ce` plugin is installed **only** in the 2026.1.1 one — correct one.
- Plugin **is loaded**: `%LOCALAPPDATA%\Google\AndroidStudio2026.1.1\python_stubs`
  has generated stub caches. So the plugin works and does detect interpreters.
- Registered Python SDKs in `options/jdk.table.xml`: `Python 3.11 (Python311)`
  → `C:\Program Files\Python311\python.exe` (has fastapi 0.115.12),
  `Python 3.13 (Python313)` → `%LOCALAPPDATA%\Programs\Python\Python313`
  (**no fastapi**), and `Python 3.11 (untitled2_360_capture_advanced)`.
- `.idea/misc.xml` binds `project-jdk-name="Python 3.11 (Python311)"`.

Conclusion: nothing is broken in the plugin. The project is simply bound to the
**system Python 3.11.8**, and the new `backend/.venv` (3.13.14, fastapi 0.162.0)
was never registered as an SDK — so it does not appear in the interpreter list.
3.11 is also invalid for this project (`requires-python >= 3.12`). Second cause
of the red errors: `backend/src` is not a Sources Root, so `sitesense.*` cannot
resolve either.

Fix is GUI-side (IDE is running; editing `jdk.table.xml` / `misc.xml` now would
be overwritten): Add Interpreter → Existing → `backend\.venv\Scripts\python.exe`,
then Mark Directory as → Sources Root on `backend/src`.

## Follow-up: how to actually launch the API on this machine

- `python` on PATH resolves to **3.11.8** (`C:\Program Files\Python311`) — the
  wrong interpreter (missing psycopg/asyncpg/aiosqlite). Do not use bare `python`.
- The **`py` launcher defaults to 3.13** (`py -0` shows `-V:3.13 *`), so
  `py -m uvicorn ...` picks the correct one. This is the recommended command.
- PowerShell rejects `"C:/path/python.exe" -m ...` — a leading quoted string is
  parsed as an expression; requires the call operator `& "C:\...\python.exe" -m ...`.
- Verified working: `py -m uvicorn sitesense.main:app --app-dir src` →
  `/healthz` returns `{"status":"ok"}`, OpenAPI reports "SiteSense API" 0.1.0.
- `.env` still targets PostgreSQL; `/healthz` works without a DB, but any DB
  route will fail until Postgres runs or the URL is switched to
  `sqlite+aiosqlite:///./var/sitesense.db`.
